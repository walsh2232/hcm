# Career-site and application-flow boundaries

Synthesized from DOC-001, Chapters 2–3; see [source dossier](../DOC-001.md).

Keep external-candidate flow types distinct:
- **Apply:** candidate submits a job application.
- **Request Information:** recruiter requests more information after the application.
- **Talent Community:** candidate expresses interests/preferences in the organization.

The guide states resume parsing is supported in job application flows, not Talent Community or event flows.

Recommended navigation sequence: configure the career site/theme/assets/pages/search; configure the appropriate flow and blocks; configure Request Information separately if needed; configure notifications and self-service; test the external and relevant internal candidate journeys end-to-end.

The guide describes **Express Apply** as supported for Job Application Flow only. It focuses on profile/resume import and surfaces fields that remain missing or invalid. It works best when the flow does not require many fields that cannot be imported. The described setup includes a Profile Import block with at least one import option, Address block v2, and enabling the feature for the flow; use the full source for exact steps.

Sources: Career Sites, printed pp. 17–90 / PDF pp. 35–108; Job Application Flows, printed pp. 91–118 / PDF pp. 109–136.
